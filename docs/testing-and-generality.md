# 测试经验、通用性与发布检查

## 审查结论

本次审查区分 **可复用核心** 与 **具体图的数据**。核心位于 `skills/image-to-tikz/`，没有按文件名、LeNet/Transformer/GMAN 名称或输入图哈希分支的代码，也不导入 `tests/`、`examples/`、`outputs/` 或参考项目。安装包只包含核心目录。

| 位置 | 内容 | 是否进入安装包 |
|---|---|---|
| `skills/image-to-tikz/scripts/` | 参数化图元、Scene 校验、OCR、渲染、采样、导出 | 是 |
| `skills/image-to-tikz/references/` | 可迁移流程与格式说明 | 是 |
| `tests/cases/` | 某张图片人工观察出的标签、坐标和裁切记录 | 否 |
| `tests/*manifest*.json` / `examples/cases.json` | 案例来源、范围和展示索引 | 否 |
| `examples/*/input.png` / `output.png` | README 输入图/高清转换图对照 | 否 |
| `outputs/` / `test-images/` | 本地完整测试证据和私人输入 | 否；不纳入版本控制 |

案例脚本中的固定坐标是该图的重建结果，不是换图时调用的识别逻辑。新图走同一个 prepare → PaddleOCR → agent 读图填写 Scene → build → 看图修订 → check → export 流程。脚本不读取案例目录推断答案。

## 已吸收的经验

- **OCR 有返回不等于全部识别。** 区分 image/图注/聚合 OCR 块；先试一个紧裁区域，再决定是否扩大补识别；记录人工补录。
- **结构按可见证据复刻。** 逐条确认箭头端点与间隙；不根据网络名称补全标准架构。Transformer 曾因此误验收，后验已明确撤销。
- **张量不是等大的框。** 可见堆叠数与通道标签分开，保留高宽深比例；立体格面和渐变都以原生图元表达。
- **线宽与灰度分开衡量。** FWHM、等效黑墨宽度和灰度分别记录；模糊图无法唯一还原原始矢量笔宽。
- **字体/字重按片段。** 中文、拉丁字体分别指定；允许局部粗体，不按“标题”角色自动加粗；检查最长文本实际边界。
- **真实首轮留证。** 首次成功编译不等于视觉通过；保留更早编译失败，不能用最终结果报告首次成功率。
- **低成本修订。** 优先修标签、端点、文字撑框、尺寸比例；builder 失败后停止依赖构建，避免重编旧 Scene。
- **图标边界清晰。** 仅独立语义 icon 可由 GPT image_gen 生成，记录 prompt/hash；文字、张量和连接不能栅格化。

对应 skill 入口为 [reconstruction-playbook.md](../skills/image-to-tikz/references/reconstruction-playbook.md)，专门校准步骤为 [first-pass-style-calibration.md](../skills/image-to-tikz/references/first-pass-style-calibration.md)。

## 首轮效率和准确性证据

两张中文路线图采用隔离的 `gpt-6-astra / high` 上下文重建，再独立复核。以下为该轮测量记录，不包含后续独立复核、skill 开发和打包时间，也不是通用速度承诺。

| 案例 | 首个成功渲染 | 完成作者自查 | 真实 OCR 请求 | 构建情况 |
|---|---:|---:|---:|---|
| 轨道交通 | 4 分 51 秒 | 9 分 33 秒 | 2 | 4 次构建；1 次编译失败；2 轮局部修订 |
| 景区三列 | 6 分 10 秒 | 9 分 12 秒 | 7 | 3 次成功编译；另有 builder 语法错误导致其中一次重编旧 Scene；1 轮视觉修订 |

首轮独立复核发现 4 类差异，共 11 个受影响元素：轨道图一个标签撑框；景区图八个分支颜色层级、一个菱形比例、一个图注数字字重。最终已修正；轨道图仍保留一处两行标签断行不同。没有完整字符/节点/边真值标注，**这些计数不能换算成准确率或错误率**。

景区图 52 个文字节点仅 9 个有 OCR 支持，其余 43 个经图像转录与核对。后续流程改成先测试一个区域，减少无收益 OCR 请求；尚无同条件对照，不能宣称节省了某个百分比。

## 本次发布验证

- 32 项回归测试：Scene/几何约束、OCR 请求与增量缓存、字体/字重、真实 XeLaTeX、原生立体图元、多类型箭头、图标哈希、冻结与过期验收。
- 安装包解压到临时目录，从无关工作目录运行 `prepare` 与 `build`，使用新的两节点中文场景，输出物理宽度设为 123 mm。
- 对同一 PDF 做 150 / 600 DPI 渲染，验证像素比例约 4 倍、裁切正常、高清导出不修改已有任务文件、拒绝覆盖目标。
- 编译测试使用 TeX Live 自带 Fandol 字体文件，消除对测试机 Songti SC / Times New Roman 的依赖。案例字体仍忠实保留，不随包分发。
- 发布前重新创建独立 Python 环境，安装公开 requirements，运行安装包 `doctor` 和新场景编译。
- 7 个案例的展示 PNG 从原 PDF 直接以 600 DPI 渲染，README 只发布输入图/高清转换图与最小来源记录，完整 PDF、TeX、Scene、资产和验收证据留在本地。没有改写已冻结任务。

自动测试中的 OCR 响应是明确标记的模拟数据；安装验证是合成场景，不冒充新真实图片的 OCR/复刻验收。历史真实 PaddleOCR 测试与自动协议测试分别看待。自动检查通过不能独立证明视觉忠实度。

本机实际验证为 macOS。仓库提供 Ubuntu CI 工作流；是否在当前提交运行成功，以 GitHub Actions 结果为准。Windows 原生环境未验证。

## 仍然依赖输入质量的事项

低分辨率文字、遮挡连线、渐变采样、真实字体身份及细小图案需要视觉判断；无法辨识时说明，不猜成确定事实。生成 PNG icon 的内部分辨率有限，即使整个 PDF/PNG 导出更大也不会增加图标细节。通用性表示流程与实现不绑定已知测试图，不表示任意新图都能一次无误复刻。
