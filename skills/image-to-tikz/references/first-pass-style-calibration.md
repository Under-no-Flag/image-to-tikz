# 首轮效率、线宽与字重

目标是减少首次构建后的返工，保留首轮证据；不是用“最终成功”冒充“一次转换通过”。

## 构建前的短检查

先把节点文字、分组、线条角色、分支端点与颜色层级列完整，再确定字体、共享字号和线宽。中文正文常规字重、英文模型名局部粗体、图注局部粗体可能共存；不按“标题通常粗体”的常识替原图加粗。填充深浅也按主分支/叶节点等可见层级归并，不仅按颜色名称合并。

OCR 与几何观察可交错进行，不必空等云端识别。首次整图识别失败时，先试**一个**紧裁文字区，确认策略有效再扩展其他区；不要一次排队提交多个同策略区域后才发现都被识别成 image。相同图片/参数使用缓存。具体是否补区域取决于遗漏和收益，不能用少数聚合块的映射率代表完整文字准确率。

## 线宽测量

在每类线条选至少两段无文字、转角、箭头头部或交叉干扰的直线。裁切框沿线足够长、横截面两侧留出背景；虚线只统计有线部分。

```json
[{"id":"box-top","role":"border","orientation":"horizontal","box_xyxy":[100,40,250,55]}]
```

```bash
python scripts/stroke_profile.py RUN/source.png RUN/stroke-samples.json --out RUN/stroke-measurements.json --width-mm 170
```

脚本输出各横截面的半高全宽 FWHM 中位数、四分位范围、峰值灰度、换算 pt；均匀浅背景时还输出等效黑墨宽度。像素→TeX pt：

`width_pt = width_px × target_width_mm / source_width_px × 72.27 / 25.4`

**宽度与深浅分开看**：模糊的浅灰细线可能 FWHM 与黑框相近，但墨量少很多。FWHM 是模糊轮廓宽度，等效黑墨宽度衡量视觉重量，两者均不能唯一恢复原始矢量笔宽。决定采用“较宽灰线”或“等效较细黑线”时记录依据；不要把二者数值混为同一个测量。彩色背景下等效黑墨量可能无效，应以干净截面与图像复核为准。

同角色采用共享值，并同时核验线色、虚线节奏、箭头头部；统一线宽不意味着所有线用同一个值。

## 中文字体与局部加粗

```json
"fonts":{"body":{"size_pt":9.25,"weight":"normal","family":"serif",
 "face":"Times New Roman","cjk_face":"Songti SC","leading":1.15,"color":"#000000"}}
```

`face` 选择拉丁字体，`cjk_face` 选择中文字体；可选 `cjk_bold_face` 指定真实粗体名称。必须使用当前环境有的字体，不能把拉丁 face 当作中文字体设置。字形与抗锯齿可能不同，显式 bold 也必须实际看渲染效果。

```json
{"text":"车站乘客head数据集构建",
 "text_runs":[{"text":"车站乘客"},{"text":"head","weight":"bold"},{"text":"数据集构建"}]}
```

runs 拼接必须等于普通 text，和 latex 不并用；未指定 weight 时继承节点字体。比如图注可以中文粗体、数字正常。不要把整段中文一起加粗以突出少量英文。渲染器仅在字重变化处加组，避免冗余字体组产生额外中文间距。

检查最长中英混排节点的实际宽度与原图换行；优先处理真实字体和冗余间距，再统一内边距或调整显式换行。不逐个缩小文字。如果保留原框与字号但换行位置不同，交付时注明。菱形中长文字会把形状撑高；需要固定图形比例时用独立原生 polygon 轮廓与文字节点，而不是忽略实际尺寸超限。

## 首轮证据与效率账目

关注首次转换时，在首次**成功渲染**后、任何图面修订前运行：

```bash
python scripts/first_pass.py RUN
```

首轮保存在 `first-pass/` 并记哈希，不可覆盖。此处成功只表示可编译，不代表视觉通过。更早的编译失败需另存日志；first_pass 不能消掉失败记录。记录开始、OCR 完成、首个成功渲染、自查完成时间，实际 OCR 请求数、成功/失败构建数、局部修订轮数；独立复核和 skill 开发时间另列，不伪装成单图转换速度。

builder 失败后立即停止依赖步骤，不能继续编译旧 scene 再算一次新结果。共享 renderer 把接近零的浮点数写成普通小数，避免 PGF 不接受 `1e-14mm` 导致无谓重编译。

独立复核分别检查首轮与修订版，列实际可见差异和剩余偏差。没有完整标注真值时，不发明“准确率99%”；节点文字、布局、字重、颜色、箭头应分项报告。最终修订通过后再冻结整个任务，连同 first-pass 和 evaluation 记录保存。
