# 样式与布局决策

涉及首轮效率、定量线宽或局部中文/英文加粗时，按 [first-pass-style-calibration.md](first-pass-style-calibration.md) 采样并记录证据。

## 线框与连线

- 按语义角色建立有限样式：处理模块、输入输出、判断、分组边框、普通关系、反馈关系。避免逐组件样式。
- 同角色线宽、颜色、圆角、填充、虚线节奏一致；保留原图支持的角色差别。
- 实/虚线、单/双向箭头可能有语义，不能为了统一而抹掉。使用共享 `arrows.meta` 箭头族，线端和线角统一。
- 连接锚点，如 `module.south`→`next.north`；端点随组件移动，不写截图像素坐标。
- 转折使用 `hv`/`vh`，回路使用 `polyline` 和相对 `via`。区分相交与汇合，不从文字猜关系。

## 字号

`font_pt_estimate` 仅按 OCR 框高和目标输出宽度换算，不是原字体的精确测量。多行、旋转文字和公式尤其需要复查。`suggested_size_group` 只是候选聚类，不能决定语义层级。

按标题/组标题/组件正文/注释建立 `fonts`，同级文本引用同一个 font key，避免 9.2、9.5、9.8pt 的独立拟合。模板 11/10/9pt 只是起点，由源图比例和实际交付尺寸校准。

优先显式换行，再调大共享尺寸或间距。有独立小字来源时才设注释角色，不因长标签溢出而单独缩字。最终检查过大、拥挤、缺字等现象。

## 尺寸、对齐、相对布局

- 先识别主轴与层级：上下阶段、左右分支、并列模块、跨组关系。锁定拓扑后规则化布局。
- 同类组件引用一个 `sizes` key；文字宽度随组宽减去共享内边距计算。
- 每个布局区域尽量只有一个 `at_mm` 根节点，其余用 `relative.of`。并列节点共享横向中心间距且 `dy=0`，纵向阶段反之。
- `layout_tokens_mm` 表达中心间距，**不是边缘间隙**。等宽 W 的组件，边缘间隙 G 对应中心间距 W+G；不同宽度需据半宽计算。
- 用 `alignments` 声明同列 x、同行 y、左/右/顶/底边对齐。核验名义尺寸与实际渲染边界。
- 分组 `fit` 引用成员，随成员移动；容器标题和交叉连线需视觉检查。
- 修改根节点应让子节点跟随，全局行列距由共享 token 调整。`scene.json` 为重新生成的权威输入，`styles.tex` 为集中风格入口。

统一应保留语义。除非用户要求，不重新设计内容、编造阶段、合并真实不同角色或改变箭头方向。
